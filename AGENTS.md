# Nexqori

Antes de trabajar, lee `ESTADO.md` en la raíz principal indicada por `git worktree list --porcelain`. Mantén un único estado por proyecto; relee antes de actualizar sólo el frente trabajado, preservando los demás. Registra fecha America/Lima, tareas concretas [ ]/[x], evidencia, bloqueos y siguiente paso. Distingue implementado, desplegado y validado. Los antecedentes no son un backlog autorizado.

Para diseño, idioma o navegación usa [.agents/skills/nexqori-brand/SKILL.md](.agents/skills/nexqori-brand/SKILL.md). Conserva la paleta elegida y las traducciones ES/EN/PT con igual cobertura.

Stack acordado: React + TypeScript, FastAPI y PostgreSQL, con Docker Compose local. La interfaz está en `src/`, la API y los fixtures coherentes en `backend/`. Lee `docs/arquitectura.md`, `docs/agente.md` y `docs/servicios-basados-en-datos.md` según el cambio. Mantén autorización en servidor, aislamiento por usuario, confirmación, idempotencia y auditoría. localStorage sólo guarda la preferencia de idioma. Los documentos originales, datos, entornos y credenciales permanecen locales.

Para el editor de atención sigue `docs/flujo-maestro-atencion.md`: un flujo compartido; elegir un caso sólo carga conversación/parámetros. Un bloque Jev clasifica y deriva primero consulta o problema y después selecciona el contrato del problema. Preguntar espera una respuesta real y retorna a Contexto hasta completar los datos, sin repetir la clasificación. Paso a paso y Flujo completo conservan el mismo estado; datos declarados no equivalen a evidencia bancaria ni autorización. Las seis ramas convergen en Contexto; acciones, especialista, seguimiento y cierre muestran qué se activaría y sus requisitos, sin ejecutar los disparadores. La plantilla separada de incidencia conserva sólo la comprobación local explícita. Contexto admite lecturas del banco sólo con sesión vigente del mismo titular y referencias seleccionadas, con auditoría y sin enviar registros ni credenciales al modelo. Resultado simple y JSON permanecen separados; seleccionar no ejecuta. Ver `docs/contexto-bancario-en-flujos.md` y `npm run test:lab:bank`. La voz sigue aplazada hasta nueva indicación del usuario.

Comprobaciones: `npm test`, `npm run build`, `python -m pytest backend/tests -q` en el entorno del backend; para cambios de recorridos o presentación, `npm run test:ui` con Docker iniciado en localhost:5180. Para conversaciones/configuración ejecuta también `npm run test:experience`; para catálogo y solicitudes específicas, `npm run test:services`. La voz pertenece a otra implementación; no instalar motores ni añadir captura de audio a esta base. La prueba visual usa registros ficticios persistentes, identificados como verificación. No publicar datos, credenciales ni PDFs del organizador. Documenta los límites técnicos y conserva el tono natural de producto en las pantallas y usa sólo destinos permitidos para el agente; sus mensajes nunca son autorización para ejecutar operaciones.

El catálogo compartido vive en `backend/service_catalog.json`. Al ampliar servicios, conserva ES/EN/PT y evidencia agregada en `notebooks/servicios_nexqori/catalog_evidence.json`; lee `docs/catalogo-servicios.md`. Los comercios del dataset no prueban convenios de recaudación. Mantén la búsqueda por necesidad y proveedor, campos específicos y la distinción entre solicitud registrada y pago ejecutado.
